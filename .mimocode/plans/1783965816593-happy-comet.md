# Plano: Tabela "De Para" Bling ↔ CIGAM

## Contexto

O sistema recebe pedidos da Bling com IDs de produto/cliente/forma_pgto/transportadora da Bling. Para enviar pedidos ao CIGAM, precisa traduzir esses IDs para os correspondentes no CIGAM. A solução é criar tabelas de referência cruzada ("de para") onde cada registro conecta o `id_bling` ao `id_cigam`.

## Arquitetura

Cada entidade terá **3 tabelas**:

| Tabela | Fonte | Descrição |
|---|---|---|
| `produtos` / `clientes` / etc. | Bling | Dados importados da Bling |
| `produtos_cigam` / `clientes_cigam` / etc. | CIGAM | Dados importados do CIGAM |
| `de_para_produtos` / `de_para_clientes` / etc. | Bridge | Mapeia `id_bling` ↔ `id_cigam` |

### Novas tabelas bridge (de para)

Cada tabela bridge contém:

```
de_para_{entidade}:
  id            UUID PK
  id_bling      STRING NOT NULL  (ID do sistema Bling)
  id_cigam      STRING NOT NULL  (ID do sistema CIGAM)
  nome          STRING NOT NULL  (descrição para consulta humana)
  ativo         BOOLEAN DEFAULT true
  created_at    TIMESTAMP
  updated_at    TIMESTAMP
```

Tabelas bridge a criar:
- `de_para_produtos`
- `de_para_clientes`
- `de_para_formas_pagamento`
- `de_para_transportadoras`

## Fluxo de Uso

### Quando recebe pedido da Bling:
1. Recebe `id_produto_bling` no webhook
2. Busca em `de_para_produtos` onde `id_bling = id_produto_bling`
3. Obtém `id_cigam` correspondente
4. Envia pedido ao CIGAM com o `id_cigam`

### Quando recebe dados do CIGAM:
1. Recebe `id_produto_cigam` na sincronização
2. Busca em `de_para_produtos` onde `id_cigam = id_produto_cigam`
3. Obtém `id_bling` correspondente
